# LangChain:模块化Agent开发框架
> LangChain的核心是**组合式开发**，把复杂的Agent拆解成一个个模块，开发人员只需要把这些模块拼起来即可。

---

> 根据自身项目需求和团队能力选择合适的工具。

- 想要快：可以从 LangChain、smolagents 入手；
 
- 想要强流程控制：可以考虑 LangGraph、CrewAI、OpenManus；
  
- 想要玩多 Agent 对话和协作：可以试试 AutoGen、CrewAI；
  
- 想要研究多 Agent 机制：可以把 Swarm 当成一个概念和代码层面的“参考实现”。

| 框架 | 核心定位 | 多 Agent 支持 | 人类协同 | 流程控制 | 工具调用 | 可视化 / 调试 | 学习成本 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| LangChain | 通用 LLM 应用开发框架 | 单 Agent 为主，可通过工具和子链实现“曲线协作” | - | 线性链式为主，复杂逻辑需靠代码实现 | 丰富内置工具，易于扩展自定义 | 无 UI，提供日志与 LangSmith 集成 | 入门易，精通难；社区生态成熟 |
| LangGraph | 基于状态图的 Agent 编排框架 | √ | √ | 图结构流程，可循环、分支跳转，支持状态持久化 | 可用 LangChain 工具或自定义函数 | 可输出流程图，支持断点续跑与状态回放 | 理解状态图需成本，但复杂流程实现更简单 |
| AutoGen | 多 Agent 对话与协作框架 | 天生多 Agent | √ | 自由对话驱动，支持群聊、经理-助手等多种模式 | 工具以对话消息方式嵌入调用，插件式扩展 | 提供监控追踪能力，与 OpenTelemetry 集成 | 接口抽象高，文档复杂，需并发与异步编程经验 |
| CrewAI | 自主协作的“AI团队”框架 | 天生多 Agent | √ | 支持顺序和层次流程，提供 Crew/Flow 两种模式 | 内置工具套件，并支持 LangChain 工具 | 无 UI，提供日志 | 模板化配置降低门槛，但高级用法需理解装饰器与流程机制 |
| smolagents | 轻量级工具调用 Agent 库 | 单 Agent 为主，可嵌套调用子 Agent | - | 基于模型生成代码顺序执行，无复杂原生流程编排 | “工具即代码调用”，高度自定义；Hub 上有丰富模型 / 工具 | 无 UI，提供日志 | 极易上手，但需开发者自行把控代码安全与复杂逻辑 |
| Swarm | 实验性多 Agent 编排轻量框架 | 通过函数显式移交控制权实现多 Agent 切换 | - | 手动设计交接逻辑，显式控制流程与上下文变量传递 | 利用 Python 函数作为工具，工具库需自行实现 | 无 UI，提供日志与流程输出 | 框架本身简单直观，但要用好需较强的任务拆解与调试能力 |
| OpenManus | 通用任务执行型 Agent | √ | √ | 内置规划 + ReAct 循环 | 内置完整工具集 | 提供日志与社区 Web UI | 入门友好，偏工程实践 |
