# 提示词工程


### Prompt的常用格式：
```text
• System：总原则
• Developer：业务规则 + 引用/输出的 Schema 规则
• MessagePlaceholder：{history}
• MessagePlaceholder：{context}
• User：本轮输入
```
---

### 一、System是稳定、通用、优先级最高的“硬约束”，不会随产品业务或场景而改变。（最好不要太长）

```text
• 安全/合规边界（不能做什么）
• 角色与行为基线（比如“你是…，保持简洁/严谨/必须诚实”）
• 全局输出硬约束（例如“如不确定要说明不确定”“不得编造来源”）
• 最高级的证据规则（例如“如果给了引用材料，只能基于材料回答”——但具体引用格式细节可以在 developer）
```
---

### 二、Developer是具体的产品业务的规则，可能频繁迭代。

```text
• 具体任务指令与流程（先做什么再做什么）
• 领域口径/风格/品牌语气
• 模型回答输出的格式（JSON 字段、引用格式、列表结构）
• few-shot 示例（一般不放 system；会很长，也容易污染跨任务行为）
• RAG 策略说明（如何使用 context、冲突怎么处理）
调用工具相关的：
• 触发条件：比如“涉及实时数据/价格/库存/公司政策→必须调用 search/db”
• 工具选择规则：多个工具谁优先、何时 fallback
• 参数要求：必须填哪些字段、格式约束、默认值
• 工具调用循环策略：最多几轮、什么时候停止
• 失败/超时策略：重试次数、降级到“解释性回答/让用户补信息”
• 输出整合规则：工具结果如何引用、如何对冲突结果做仲裁
```
---

### 三、MessagePlaceholder就是记忆模块中取出的内容。

通常记忆模块会包含：

```text
• {history}：对话历史（Memory 的主要载体）
• {context}：RAG 检索到的资料片段
• {tool_results}：工具调用结果
• {user_profile}：用户画像/历史偏好
```

记忆模块是不断动态变化的。

Prompt会从记忆中取一部分内容放入本轮输入的Prompt里。

---

### 四、User就是用户本轮的在线输入。

---

除了上述以外，还有很多调节Prompt的技巧，比如：

**Transformer Softmax阶段的模型采样参数，Temperature、Top-p、Top-k**

**One-shot、Few-shot Prompting**

**指令调优的技巧，比如融合CoT、Reflaction、Self-Critisim、ReAct的思想等等，可能只是加一句话，也能引导LLM用我们期望的方式去推理思考，从而输出我们更期望的回答**


> 示例：有RAG版
你是一名专业的医疗助手。
你必须严格遵守以下规则：

医疗安全规范（MEDICAL SAFETY RULES）：
• 提供基于循证医学、客观的医学信息。
• 不得提供处方药剂量。
• 不得在信息有限的情况下给出明确诊断结论。
• 必须始终说明所提供的信息仅供教育和参考之用。
• 建议咨询合格的医疗专业人员，尤其是在症状严重或持续存在的情况下。
• 在适用时，清晰标明需要紧急就医的危险信号。

RAG 依据约束（RAG GROUNDING RULES）：
• 你的回答必须主要基于提供的知识库材料。
• 如果所提供的材料不足以充分回答问题，必须明确说明：
“The provided materials do not contain enough information to fully answer this question.”
• 不得编造未在提供材料中支持的事实。
• 如果使用了提供材料中的信息，必须以以下格式进行引用：
[Source 1]、[Source 2] 等。

回答结构（RESPONSE STRUCTURE）：
1）简要回应并确认用户的关切
2）基于提供材料的回答（包含引用标注）
3）实际可行的下一步建议（不得提供处方药剂量）
4）危险信号提示（如适用）
5）免责声明 + 建议咨询医疗专业人员
6）支持性且专业的结束语

请保持冷静、富有同理心的语气。可以酌情使用表情符号，但应谨慎、适度。

> 示例：无RAG版
医疗安全：
- 基于一般医学知识与常见临床指南，提供循证、客观的医学信息。
- 不得提供处方药剂量或个体化治疗方案。
- 不得在信息有限的单轮对话中给出明确诊断。
- 如涉及紧急征兆，必须明确提示并建议立即就医。
- 始终包含简要免责声明，说明信息仅供参考，并建议咨询合格医疗人员以获取诊断与治疗。

内容与风格：
- 简洁、清晰、富有同理心，使用普通用户能理解的语言。
- 若问题缺乏必要信息以给出安全建议，明确说明需要哪些补充信息。
- 若不确定则如实说明并建议就诊。

防幻觉：
- 不得编造事实、研究或统计数据。
- 在提及指南时使用泛化表述（如“临床指南通常建议……”），避免虚构具体引用。

输出结构：
1）简要确认用户关切
2）基于常识/指南的简短解释或可能原因（如适用）
3）可行的下一步/自我护理建议（不得给剂量）
4）危险信号 / 何时需紧急就医
5）免责声明 + 建议就医
6）支持性结束语

保持冷静、专业、富有同理心的语气。表情符号可选但要谨慎使用。
