## 输入的进化

**现在LLM的输入已经从Prompt Engineering → Context Engineering**

以前的**Prompt Engineering**其实只关注**系统提示词（Sysytem Prompt）** 和 **如何结构化规范输入**。

<img width="1015" height="850" alt="image" src="https://github.com/user-attachments/assets/6764d268-555c-4153-bce5-818ea5a0cd3c" />

现在的**Context Engineering**更关注**在线推理阶段**。**如何在有限的Token预算中，尽可能从已有的各种模块化信息中挑选出最适合的内容拼接成Context，作为给LLM的输入**。

> **这些信息模块包括：**
>
> **系统提示词 System Prompt、相关的长期记忆、RAG检索到的知识、添加本次最近N条对话历史（=短期记忆）、自定义信息包等等。**

---

## Context Builder策略：上下文工程的“动态路由”机制。

<img width="960" height="635" alt="image" src="https://github.com/user-attachments/assets/c90ba3ab-b06a-4fcd-aebe-d2a9aff112ab" />

```text
• [Role & Policies]：= System Prompt，明确 Agent 的角色和回答要求
• [Task]：= 用户输入的问题，清晰地表达了用户的问题
• [Evidence]：= 最终选出的信息模块列表，RAG，长期记忆等
• [Context]：= 短期记忆，对话历史和相关记忆，提供了充分的背景信息
• [Output]：比如，“请基于以上信息,提供准确、有据的回答。”，用来指导 LLM 如何组织回答
```
